An illustration, not a result

Two solvers, the same questions

Say two people each write a program that factors big numbers. Both are given the same 100 numbers, made from a secret number that nobody could see in advance. The first program takes 40 seconds on the hard ones. The second takes 5. That is 8 times faster, or 3 bits. This site is a way for a stranger to confirm a claim like that without taking anyone's word for it.

From a declaration to a certificate

1

Describe the problem

Write three small pieces: how to make a test question from a secret number (with the answer hidden inside), how to check an answer exactly, and a plain baseline solver to compare against.

python3 compile_domain.py init mything
2

Compile it into a test

The compiler checks that your problem can't be gamed, times your baseline, picks the test sizes and time limit, and works out what size of speedup it can actually prove. It ends with READY or NOT READY.

python3 compile_domain.py compile mything
3

Get a certificate

After a round, one file holds the claim, the rules, the secret numbers and every raw measurement. Anyone can recompute the result from it, and checking it never runs the file's code unless you ask. It cannot show the CPU costs were honestly measured: that needs the verified sandbox, or re-running instances yourself.

python3 certificate.py verify x.cert.json

The compiler and certificates are built and tested, but no round has run on a verified sandbox yet, so no certificate here is official. Domains shows what each test can and can't prove; the guide explains how to write a problem and check a certificate.

AI and benchmarks

Verifiable AI measurements

Someone says their model is faster, their kernel is better, their inference costs less. How would you check? The same protocol works here: committed instances, measured costs, certificates anyone can recompute.

Counted operations

Every tensor operation is charged a cost from its shapes. Anyone can re-run any record and must get exactly the same counts, on any machine. It proves a solver needs fewer operations (a cache, pruning, an early exit). It cannot show that a solver is faster at the same arithmetic.

Timed inference

The full protocol applied to model inference: classify a committed batch, seeds first, certificate after. The same protocol as the algorithmic problems; the locked box itself has not yet run an official round, so nothing here is certified.

GPU time

The operator's clock on one pinned device. Weakest evidence: it can be re-measured on the same hardware but never re-executed exactly. It says what happened on one machine, nothing about another.

Each gives different evidence and each says what it cannot show. Full details on the Domains page. AI measurements use the same certificates and attestations as everything else: certify a result without entering a competition, or compete in a round.

How a test stays fair, in four steps

1

Commit

Before anyone submits, the judge publishes a fingerprint (a hash) of a secret number. Every test question is generated from that number, so nobody can prepare answers in advance, and the judge can't swap the questions afterwards.

2

Solve

The submitted solver and the baseline get the same questions, one process each, with a time limit. Every question has a known answer hidden inside it, so every one can be solved.

3

Check

Every answer is checked exactly. A wrong or missing answer is charged the full time limit, so giving up on the hard questions can't look like being fast.

4

Score

Questions are grouped by how hard the baseline found them. The score is a cautious estimate of the speedup on the hardest groups: a number we are 95% sure the true speedup is at least as large as. A lucky run can't inflate it.

Words used on this site

Bits
How we count speed. Each bit doubles it: 3 bits is 8 times faster.
Baseline (reference solver)
The plain, standard solver every other solver is compared against.
Instance
One test question. A solver gets it and must return an answer.
Size ladder
The list of question sizes used, from easier to harder.
Time limit (CPU cap)
The most CPU time one question may take. Failing or timing out is charged the full limit.
Seed and commitment
A secret number that every question is generated from, and its published fingerprint. The fingerprint proves the questions were fixed before anyone submitted.
Certificate
One file with the claim, the rules and every raw measurement, so anyone can recompute the result.
Official (certified)
A result measured inside the strict, locked-box test environment, on three independent secret numbers, at the problem's full question count and time limit. No result on this site is certified yet.
Locked box (sandbox)
A sealed environment that runs other people's programs so they cannot read the answers, hide work or tamper with the timer.
Round
One contest: the secret numbers are fingerprinted first, solvers are submitted until a deadline, then everything is run and the secrets are revealed.
Lattice, factoring, dlog
The puzzle types used so far: finding a short vector in a grid of points; splitting a big number into smaller ones; finding the exponent in a modular power (the discrete logarithm).
Exact count (step counting)
Counting the Python instructions a program runs instead of timing it. Anyone on the same Python version gets the same number, so nobody has to trust a clock or a computer.
