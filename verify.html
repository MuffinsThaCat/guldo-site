Verify

Check a certificate yourself

A Guldo certificate is a claim about an AI agent that you should not have to take on trust. Point this page at a result bundle and your own browser re-checks the signatures, the hash-chained log, the seed commitment and the registration. Nothing is uploaded and there is no account: the page is a small script you can read.

What a pass means, and what it does not

A pass means the bundle is internally consistent and every signature in it was made by the key you named: the log has not been edited, the seed revealed afterwards is the one committed to before any agent ran, the round was registered before it ran, and the certificate says what the signed numbers say.

It does not mean the verifier is honest or independent. A key is not a person. Only you can decide whose key to trust, so take it from the verifier's own publication, not from the person who sent you the certificate.

It is narrower than the full audit. Re-deriving every task from the seed and replaying every tool call needs the Python code; this page lists what it skips next to every result.

Status, plainly: no independent party has run a round yet. The demonstration bundle below was run by one person playing every role on one laptop; it shows the machinery works, not that any real verifier can be trusted. See Agents.

1. The verifier's public key

One key per line (a # name comment is fine). Without one, the page can only tell you the bundle is consistent, and says so.

Optional: the other parties in the joint seed

If the seed was made jointly, you can pin each party's key too, and say which party is the verifier so the page can check that operator, vendor and verifier used different keys.

The full audit, on your own machine

The browser checks are a subset. The audit also re-derives every instance from the revealed seed, replays every session and regenerates every certificate. It needs Python 3.9+ and the downloadable tool from the Install page.

python3 agent_verifier.py audit BUNDLE --trusted VERIFIER_KEYS --party-keys PARTY_KEYS --verifier-party verifier --require-registry --require-joint

For authors who want to cite a result

Publish the bundle folder somewhere readers can fetch it (with cross-origin access allowed) and link to verify?bundle=ADDRESS&key=VERIFIER_KEY. Readers who follow the link get the checks above with no setup. The key in a link comes from you, the author, so a careful reader will compare it with the verifier's own publication; the page says so whenever a key came from a link.
