Log

A public record of verified certificates

A certificate proves one measurement to whoever holds the file. The log makes measurements findable and permanent: every certificate it accepts is verified first, then added to an append-only list that cannot be edited, reordered or quietly shortened without the change being provable.

This log's witnesses are named by its operator. 0 co-signature(s) come from keys the operator lists in trusted.txt and 1 from other keys. The operator chose that list, so it does not show the witnesses are independent of the operator. Pin the witness keys you trust yourself (--trusted) before relying on them.

    • As logged is whatever the entries say. An entry no one has re-checked can carry any credit its operator wrote.
    • Re-checked means this build recomputed the entry from its certificate and got the same answer. That proves the certificate's instances come from its seeds and its numbers follow from its records, not that its clock readings are true: in a timed certificate they are the submitter's own.
    • Re-executed means a signed attestation says someone re-ran instances of this certificate on their own machine, and every check in it passed, including the re-run (identical counts for a step-counted certificate, a timing within tolerance otherwise). It is that person's statement about their own machine.
    • Run in the sandbox means the sandbox operator signed that their own records of the run are, byte for byte, the certificate's ladders. No such statement exists unless the operator has run a round: the locked box has not yet run an official one.
    • “Listed key” means a key in the operator's trusted.txt. The operator chose that list, so it does not show independence: ask with your own keys, guldo log frontier --tier reexecuted --trusted YOURKEYS.

    How it works

    1

    Submit

    The operator verifies a certificate (nothing in it is executed), then appends one line describing it to a Merkle tree (a list that has a single fingerprint, which changes if any entry is altered). A certificate that does not verify, or is the same measurement as one already logged (unless it carries strictly more evidence), is refused and leaves no trace in the tree.

    2

    Sign

    The operator signs the tree head: how many entries there are and the one hash that commits to all of them. Two different heads for the same size would be a signed contradiction, so a log cannot show different people different histories without being caught.

    3

    Witness

    Independent parties, on machines the operator does not control, check that each new head only extends the last one they saw, and co-sign it. A reader who trusts any one of them knows the log was not rewritten.

    Check it yourself

    You need pip install "guldo-cli[attest]" for signatures. Nothing here trusts this site: the commands read the log's files and recompute.

    guldo log check --log https://guldo.org/log --log-key 5f544602190d928762debb21148d28cab881b1e926c56d1a57dfea95b905afb3 --recheck
    guldo log prove --log https://guldo.org/log --cert my.cert.json --out proof.json
    guldo log verify-inclusion proof.json --cert my.cert.json --log-key 5f544602190d928762debb21148d28cab881b1e926c56d1a57dfea95b905afb3

    The first audits the whole log: every entry in order, every head ever signed as the root of its own prefix, every signature, and (with --recheck) every certificate recomputed against its entry. The second and third give you one small file that proves a certificate is in the log, which you can hand to anyone and which they can check offline.

    Show that nobody has done better

    The log can give a claim of the form “no certificate submitted to this log reaches T bits on this problem”, and anyone can recompute it from the log’s own entries.

    guldo log absence --log https://guldo.org/log --family PROBLEM --threshold T --out claim.json
    guldo log check-absence claim.json --log https://guldo.org/log --log-key 5f544602190d928762debb21148d28cab881b1e926c56d1a57dfea95b905afb3 --recheck

    Ask for stronger evidence, with your own keys

    A credit in a timed certificate is its submitter’s own measurement. The log also commits signed statements by people who re-ran a certificate, and by the sandbox operator about their own records of a run. Which keys to believe is your decision, so you supply them: a file of public keys, one per line.

    guldo log frontier --log https://guldo.org/log --tier reexecuted --trusted my-keys.txt
    guldo log frontier --log https://guldo.org/log --tier run --trusted operator-key.txt

    Be your own witness: remember what you saw

    No one needs to recruit anyone for this. Keep the last head you saw in a file; the next check fails if the log was rolled back or the history you saw was rewritten, and a rewritten history writes a file that proves, to anyone offline, that the operator signed two contradictory histories. It protects you, and anyone you show the file to; it does not protect people who never looked.

    guldo log check --log https://guldo.org/log --log-key 5f544602190d928762debb21148d28cab881b1e926c56d1a57dfea95b905afb3 --remember ~/.guldo-seen.json

    Become a witness

    Anyone can. Run this on a schedule from a machine the operator does not control; it refuses (and keeps your old state) if the log was rolled back, rewritten, or shown to you differently than before. Send the co-signature file to the operator or publish it; the operator merges it. It counts as independent for a reader only if that reader chose to pin your key.

    guldo log witness --log https://guldo.org/log --state ~/.guldo-witness.json --key witness.key --log-key 5f544602190d928762debb21148d28cab881b1e926c56d1a57dfea95b905afb3 --recheck --out cosig.json

    What the log does not show

    • Not being in the log means not submitted, not that it does not exist. Nothing forces anyone to submit. A claim that no one has done better covers the certificates on this record and no others.
    • A logged certificate is not a verified speed, and the log does not know whether it is official. The log checks that a certificate verifies. Whether the recorded timings were honest is exactly as open as on the Limits page, and the OFFICIAL label is written by whoever builds the certificate.
    • The operator's timestamp is the operator's. A witness's co-signature time, and a head published somewhere the operator cannot edit, are the earliest times someone else can vouch for.
    • A signature shows which key signed, not that its owner is independent. An operator can mint five keys, so only keys you pinned count for you; the operator's own list of witnesses proves nothing about independence.
    • A witness that does not re-check certificates vouches only that the log is append-only, not that each entry says what its certificate says. A witness that re-checks refuses to vouch for entries it cannot re-check. A reader can re-check any entry alone.
    • An old head is still a valid head. A mirror that stopped updating looks like a log that stopped. guldo log check --log URL --log-key KEY --max-age-hours 48 fails on a head that is too old; the operator is expected to sign a heartbeat daily. A function on this site’s own hosting signs a fresh head every day. It also timestamps the head in Bitcoin, collects finished proofs and asks the Internet Archive to keep a copy. The “Right now” block shows when it last ran, and says so plainly if it stops.
    • Heads are never withdrawn. A mistaken entry can be answered by a later entry or a note, never by deleting it.
